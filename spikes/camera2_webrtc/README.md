# Спайк этапа 1: Camera2 + WebRTC

Не продакшн-код (SPEC 12, этап 1): проверяет главный риск — можно ли менять ISO, фокус, зум и остальное **во время трансляции**, не перезапуская поток. Строки интерфейса здесь не локализованы: спайк выбрасывается после этапа.

## Что делает

1. Включает камеру через flutter_webrtc: 1920×1080, 30 fps, задняя камера.
2. Гоняет видео через WebRTC-соединение внутри самого телефона (loopback): видео реально кодируется (сначала H.264) и декодируется, как по пути на медиа-сервер. Сервер не нужен.
3. Меняет параметры камеры способом **(а)** из SPEC 6.2: Kotlin-код (`android/.../Camera2Control.kt`) находит Camera2-сессию, которую открыл flutter_webrtc, и заменяет её повторяющийся запрос на запрос с ручными настройками. Так же flutter_webrtc сам выставляет зум и фокус.
4. Проверяет по `CaptureResult`, что камера реально применила настройку, и меряет, за сколько миллисекунд.

## Как проверить на телефоне

1. GitHub → Actions → «Stage 1 spike (Camera2)» → последний прогон → артефакт `camera2-spike-apk` → скачать, распаковать `app-debug.apk`.
2. Поставить на телефон (разрешить установку из неизвестных источников), открыть «Camera2 spike», «Включить камеру», разрешить камеру.
3. Нажать «Автотест», дождаться «Автотест пройден / НЕ пройден», нажать «Копировать отчёт» и прислать отчёт.
4. Можно и руками: у каждого параметра режимы auto / manual / preset и ползунок, рядом — значение, которое сообщает камера.

Без телефона то же самое делает CI на эмуляторе Android: артефакт `camera2-spike-emulator-report` (`spike-report.json` и полный лог).

## Что в отчёте

- `device` — производитель, модель, Android, версия HarmonyOS (на HarmonyOS NEXT Android-приложения не запускаются вообще);
- `camera` — уровень поддержки Camera2 (`legacy` / `limited` / `full` / `level_3`), возможности (`manual_sensor` нужен для ISO и выдержки), реальное разрешение и fps;
- `results` — по каждому параметру: поддерживается ли, что запросили, что сообщила камера, за сколько мс применилось (норма — до 1000 мс, SPEC 6.5);
- `stream` — кодек и кодер, разрешение и fps на отправке и приёме, сколько кадров декодировано за тест (поток не должен остановиться).
