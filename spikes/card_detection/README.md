# Спайк: распознавание карт готовой моделью

Проверка, насколько готовая модель узнаёт открытые карты на видео со стола. Это не продукт: в приложения и
на серверы отсюда ничего не попадает.

## Модель и лицензии

- Модель: [`sroot/lgd-cards-gen3`](https://huggingface.co/sroot/lgd-cards-gen3), YOLO11s, 52 класса (ранг + масть).
  Находит угловые индексы открытых карт; углы одной карты скрипт сводит в одну карту. Рубашку не распознаёт.
- **Лицензия весов AGPL-3.0**: только для этого внутреннего теста. В продукт идёт своя модель на детекторе с
  лицензией Apache-2.0, обученная на открытом датасете (Public Domain) и на кадрах наших столов (см. SPEC 10.2).
- Запуск без кода Ultralytics: `onnxruntime` (MIT), `opencv-python-headless` (Apache-2.0), `numpy` (BSD).

## Установка

```bash
cd spikes/card_detection
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
python download_model.py        # ~38 МБ в model/, проверяется по sha256
```

## Запуск

С сервера клуба, в живую, на несколько секунд позже камеры (нужна камера на H.264, то есть эталонный телефон:
скрипт читает ту же запись, что перемотка):

```bash
python watch.py --server http://IP-сервера:8000 --key КЛЮЧ-КЛИЕНТА [--table 1]
```

В админке он появится как компьютер «Card recognition test». Раз в секунду печатает найденные карты с
уверенностью, а при каждой смене набора карт сохраняет кадр с рамками в `out/live/`.

Из файла: `python watch.py --video стол.mp4` (видео с рамками в `out/`) или `python watch.py --image фото.jpg`.

Параметры: `--conf 0.4` (порог уверенности), `--tile 400` (меньше плитка — мельче карты, но медленнее).

## Что уже проверено (22.11.2026)

- **128 реальных фото с разметкой** (RF100 poker-cards, CC BY 4.0), `python evaluate.py --data …`:
  ранг определяется с precision 0.94 и recall 0.86. Масть на этом наборе честно не измерить: примерно у трети
  фото разметка сдвинута на один класс (♠ размечена как ♥), модель на них права — проверено глазами.
- **Вся цепочка**: тестовая камера показывала карты (`BOT_FAKE_VIDEO` в `tools/`), сервер писал запись,
  `watch.py` её читал: 15 карт на кадре 960×540, ранги и масти совпадают с картинкой.
- **Скорость на процессоре** (4 ядра): 70 мс на кадр 640×640, 0,5–0,7 с на кадр 1080p с плитками. Это
  1–2 кадра в секунду на стол; для 10 столов нужна видеокарта.
- **Мелкие карты под углом пропускает**: карта меньше ~100 пикселей в кадре находится плохо. Камеру лучше
  направлять на зону раздачи, а не на весь стол.

## Что дальше

Настоящая точность — только на видео наших столов: снять несколько раздач при обычном свете клуба, прогнать
`watch.py`, разметить ошибки. Тогда решаем, хватает ли готовой модели для показа или сразу обучать свою.
